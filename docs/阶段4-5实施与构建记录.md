## 阶段 5：核心结构整理

原 run_execution.py 1,561 行，当前主协调器 803 行。拆分采用组合：

- run_execution.py：串行编排、服务分派、事件发布及原调用接口。
- run_execution_state.py（497 行）：排队、恢复、显式重启、检查点兼容和结果持久化。
- run_execution_inspection.py（210 行）：只读运行检查和来源类型策略。
- run_execution_outcomes.py（254 行）：不可变运行结果、事件所需检查内容与状态转换。

这是职责拆分，不能将移到新模块的行数当作净删除。原入口及测试使用的兼容接口仍可调用。

作者定位方面，dom_read.py 共享可见候选、文字、属性、规范化和只读轮询；author_location.py 共享按精确作者名提取候选主页 ID。各调用方的名字匹配、URL 路径识别、关注文案和等待策略仍作为明确规则保留，写入仍要求唯一目标。

来源接口统一提供 Sequence[ReadlistCandidate] 与 SourceArticleObservation。HTTP 信封和候选转换只实现一次，标题族、精确名称和年份继续各自筛选。compatibility.py 集中接收旧 dict 选择结果和未提供 observe_article 的旧适配器。

旧 source_like_plan、source_like_execution、source_like_write_test 实现移至 backend/legacy；原 use_cases 路径保留公共名称导出。主应用使用 source_like_automation，生产 PYZ 依赖清单未包含 backend.legacy。旧授权词、检查点和历史数据读取保持兼容。

本次不涉及账本拆表；1.5.4 → 1.5.5 没有新增数据库迁移。授权检查、单任务槽、写前检查点、未知结果不自动重试保持原有规则。

## 打包时发现并修复的退出问题

实机刷新后关闭页面曾在 45 秒内无法退出。日志出现 Windows WinError 10054；本机 Python 3.12.10 的 proactor 连接关闭函数在 socket.shutdown 抛异常后可能跳过 server._detach，导致 asyncio 的 server.wait_closed 一直等待。

desktop_server.py 配置 timeout_graceful_shutdown=5，让连接清理有截止时间，然后继续应用 lifespan 的任务、浏览器及数据库清理。没有设置 force_exit 跳过应用清理。新增模拟永久等待监听器的测试，确认仍到达应用清理。

最终 EXE 新库和旧库两种场景均通过 15 秒退出窗口检查。测试不会访问 B 站或执行真实抽奖操作。
