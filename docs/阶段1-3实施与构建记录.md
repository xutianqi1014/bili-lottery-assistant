## 阶段 2：执行计划与发现数据

- execution_plan.py：每个 PlannedItem 独立携带 family/source_section，落库不再串用上一轮局部变量。

- DiscoverySelection 主键加入 readlist_id，同篇专栏在多个合集中的上下文均保留；同一上下文重复添加幂等。
- discover_source.py：每次发现缓存已检查专栏，只检查一次点赞状态和正文，仍保存各合集上下文；唯一专栏统计不重复。
- 旧 SQLite 关联表升级前自动生成同目录 .pre-stage123-*.bak，使用 SQLite backup API 并校验完整性。
- 表重建放在显式事务内，检查字段及行数；遇到未知自定义列中止，避免静默丢失。重复启动不再重复升级。
- 备份连接显式关闭，避免 Windows 文件占用。现有 Run/RunItem 历史保留；不能恢复旧版本此前已覆盖的数据。

## 阶段 3：运行与前端稳定性

- 来源点赞收尾默认上限从 10 调为 15；环境变量自定义值仍有效。执行预览显示实际上限和来源数量。
- 超限仍整体停止，写入结果不明确仍禁止自动重试；未扩大授权范围。
- JobRunner 完成、异常和启动前取消均清理任务引用，保护同 ID 新任务，不破坏串行任务槽。
- 前端使用工作区代次和刷新序号丢弃旧响应；同类并发刷新合并，必要时补刷一次。
- 只保留一个发现轮询定时器；页面退出清理监听使用的资源，断线重连后同步当前工作区。
- 来源切换后忽略旧任务事件及确认响应，避免延迟确认触发旧计划启动。
- 重绘保留实际设置表单节点、焦点及未保存内容；防止重复提交监听，不把密钥草稿额外持久化。

## 重建命令

在仓库根目录，以可用的 Python 3.12 创建虚拟环境；以下示例使用 uv：

```powershell
uv venv --python 3.12 .venv-stage123
uv pip install --python .venv-stage123/Scripts/python.exe -r packaging/windows/requirements-build.txt
uv pip install --python .venv-stage123/Scripts/python.exe --no-deps -e .
pnpm --dir frontend install --frozen-lockfile
.\.venv-stage123\Scripts\python.exe -m pytest --basetemp build/pytest-fresh-validation
.\.venv-stage123\Scripts\python.exe -m ruff check backend tests
.\.venv-stage123\Scripts\python.exe -m mypy backend
pnpm --dir frontend test
./packaging/windows/build.ps1
.\.venv-stage123\Scripts\python.exe packaging/windows/smoke_test.py dist/v1.5.4/BiliLotteryAssistant/BiliLotteryAssistant.exe
.\.venv-stage123\Scripts\python.exe packaging/windows/smoke_test.py dist/v1.5.4/BiliLotteryAssistant/BiliLotteryAssistant.exe --legacy
```

pytest 的 --basetemp 应选未使用的测试目录，不能指向用户数据目录。EXE 冒烟测试仅放行本地控制台地址，禁用三类自动写入，使用临时数据库和无头 Edge。重建后需重新生成 ZIP 与哈希，不应沿用本记录校验值。

## 升级和回退

先退出旧版再启动新版，不能同时运行多个版本。自动备份位于实际数据目录内数据库旁，不在 EXE 目录内。回退前关闭所有程序、另存当前数据库，再恢复对应升级前备份并运行旧版；备份后的新记录不会随旧备份恢复。不要让旧版本直接打开升级后的数据库。
