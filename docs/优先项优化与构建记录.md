# 优先项优化与构建记录

日期：2026-09-20。版本：1.5.6，本地中间构建，相关变更后随 v1.6.0 首次发布。基于 v1.5.5（f476de1）实施冗余复查的三项优先改进。

## 运行数据复用

- `ExecutionPlanService.get_snapshot` 在同一会话内读取运行、条目和收尾结果。SQLite 显式开启读事务，避免默认 sqlite3 模式中连续 SELECT 不进入同一数据库快照的问题。
- 创建、查询、确认、启动、恢复及重新开始的运行响应使用该快照；序列化时不再通过执行服务重新读取运行和条目。
- `calculate_source_closure` 和 `SourceClosureService.calculate` 接收可选的已有条目列表。未传列表的原调用方继续自行查询；空列表作为实际输入处理。
- `RunExecutionStore.persist_outcome`、`refresh_source_closure` 将用于统计的同一批条目传入收尾计算。写后查询仍触发会话正常刷新，保持统计反映最新条目状态。

查询计数回归覆盖 1 条和 100 条动态：运行响应的 Run SELECT 和 RunItem SELECT 均为 1 次；刷新收尾只读 1 次条目列表；保存结果包含 1 次目标条目主键读取及 1 次条目列表读取。来源、问题记录和动态更新所需的查询仍照常执行。

## 日志页增量显示

- 日志追加按 16 毫秒窗口合并。计划刷新、页面切换和释放视图时取消等待中的日志刷新，避免随后再重复绘制。
- 日志行使用递增 ID；只追加新行、淘汰超过 500 条上限的旧行。导航、已有日志行、复制及清空按钮保留原 DOM 节点和事件监听。
- 日志数量、详细模式提示、按钮禁用状态及运行阶段状态局部更新。
- 过期计划响应不再触发绘制；现有来源切换保护、表单保留和日志脱敏继续生效。

节点身份、合并次数、500 条上限、日志转义与脱敏、清空按钮以及销毁时取消调度均有回归检查。其他页面仍使用原有完整绘制方式；本次没有对所有页面进行组件化重构。

## 执行事件统一

执行协调器中的 6 处 `run.item_updated` 和 8 处带动态信息的 `run.waiting_user` 改为共享发布方法。调用方继续决定状态转换、收尾刷新、问题记录及返回值；官方、预约、非官方和只读分支的取消与失败处理保持原有规则。来源收尾事件继续使用自身的字段结构。

回归检查覆盖官方与预约终态的事件字段、暂停原因及先结果后暂停的发布顺序；完整后端测试覆盖既有执行路径。
