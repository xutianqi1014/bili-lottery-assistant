# B站互动抽奖助手使用说明

版本：`0.1.0`

适用程序：`BiliLotteryAssistant.exe` 或源码启动的本地 HTML 控制台
默认地址：<http://127.0.0.1:8787/>

## 1. 软件用途与当前支持范围

软件读取已配置 UP 的 B 站图文/专栏来源，生成动态候选，再依据用户确认的不可变运行计划处理官方和非官方互动抽奖。

当前代码只注册一个来源：

| 项目 | 当前值 |
|---|---|
| UP MID | `100680137` |
| 来源页面 | <https://space.bilibili.com/100680137/upload/opus> |
| 适配器 | `lottery_toolman_v1` |
| 每类来源专栏 | 最新 5 篇 |
| 来源类别 | 普通抽奖合集、官方抽奖合集 |

其他 UP 的来源结构不能直接套用当前适配器；需要增加独立来源配置和适配器后才能使用。

## 2. Windows 版安装和启动

### 2.1 下载

从 GitHub Release 下载：

<https://github.com/xutianqi1014/bili-lottery-assistant/releases/tag/v0.1.0>

文件名：`BiliLotteryAssistant-windows-x64-v0.1.0.zip`

下载后解压到一个有读写权限的目录。不要只复制 `.exe` 文件，必须保留同级 `_internal` 目录。

### 2.2 启动

双击：

`BiliLotteryAssistant\BiliLotteryAssistant.exe`

程序会：

1. 检查 `127.0.0.1:8787` 是否已是本软件服务；
2. 如果已经运行，只打开已有控制台，不启动第二个服务；
3. 如果端口空闲，启动本地 FastAPI 服务；
4. 服务监听成功后自动打开 `http://127.0.0.1:8787/`。

如果 8787 已被其他程序占用，程序会报端口占用错误，不会强制结束其他程序。请关闭占用程序后再启动。

### 2.3 关闭和释放端口

关闭所有打开的本软件控制台页面后，程序等待约 3 秒确认没有页面重新连接，然后停止任务、关闭浏览器和数据库并释放 8787 端口。

刷新控制台页面不会立即停止程序：页面会在约 3 秒宽限期内重新连接。若同时打开多个本软件页面，必须全部关闭才会触发退出。

## 3. 源码启动

要求 Python 3.12 或更高版本：

建议首次使用前在 PowerShell 终端完整运行一次下面的初始化命令。它会重新创建项目虚拟环境、安装开发依赖、安装 Playwright Chromium，并让本次启动使用该 Chromium；以后再次启动时可直接激活 `.venv` 后运行最后两行。

```powershell
deactivate
Set-Location C:\Users\35267\Desktop\b站抽奖\bili-lottery-assistant

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install -e ".[dev]"
python -m playwright install chromium

$env:BILI_BROWSER_CHANNEL='chromium'
python -m backend.launcher
```

然后打开：<http://127.0.0.1:8787/>

其中 `$env:BILI_BROWSER_CHANNEL='chromium'` 只对当前终端窗口有效。若不设置该变量，源码默认使用 Microsoft Edge（`msedge`），需要系统已安装 Edge。浏览器登录资料保存在本机应用数据目录，不会提交到 GitHub。

## 4. 首次登录和登录页规则

1. 打开控制台首页“概览与准备”。
2. 点击“打开登录页”。
3. 在自动打开的 B 站浏览器页面完成登录、扫码或验证。
4. 登录完成后返回控制台，点击“开始只读发现”。

登录页具有唯一性：

- 登录页已经打开时，再次点击只会把已有页面切换到前台，不会重复新建页面；
- 关闭登录页后再次点击，会重新创建登录页；
- 自动化浏览器被关闭后再次点击，会重新创建浏览器会话；
- 不要在执行期间手动关闭或操作自动化使用的 B 站页面。

## 5. 首页运行配置

首页的“DeepSeek 与提及好友配置”表单对应 `/api/settings` 接口。

### 5.1 DeepSeek 字段

| 字段 | 作用 |
|---|---|
| DeepSeek API Key | 生成非官方动态评论；输入框为密码框，接口只返回是否已配置 |
| API 地址 | 默认 `https://api.deepseek.com/chat/completions` |
| 模型 | 默认 `deepseek-v4-flash` |
| 固定 @账号 1–3 | 动态要求 @好友时按顺序补充，最多 3 个 |

点击“保存设置”后，Key 只保存在当前 Python 进程的设置对象中，不写入数据库、运行计划或日志；关闭程序后需要重新输入。

### 5.2 安全要求

- 不要把 Key 写进代码、截图、问题网址或 GitHub Issue；
- API 地址必须是带主机名的 `http` 或 `https` 地址，不能携带用户名和密码；
- 动态要求的 @好友超过 3 个时，程序在任何 B 站写操作前阻塞该条；
- 未配置 DeepSeek 时，非官方条目不会在评论写入前继续执行。

## 6. 三页界面和按钮

### 6.1 概览与准备

显示本地服务健康状态、浏览器会话状态、当前来源和运行配置。主要按钮：

- “打开登录页”：调用 `POST /api/account/open-login`；
- “保存设置”：调用 `POST /api/settings`；
- “打开 B 站主页”：打开当前来源配置的 UP 专栏页。

### 6.2 来源发现

主要按钮：

- “开始只读发现”：调用 `POST /api/source-profiles/{profile_id}/discoveries`；
- “刷新”：调用 `GET /api/discoveries/{discovery_id}` 和问题列表接口。

发现卡片显示：

- 已检查专栏数；
- 未知标记数；
- 动态 ID 全局去重后的数量；
- 自动计划状态；
- 两类来源专栏的点赞判定、解析状态和决策；
- 动态候选与它们的来源关系。

只读发现阶段不打开候选动态，不读取评论列表，也不执行候选动态的评论、转发、点赞或关注。

### 6.3 执行与结果

如果发现后没有待处理动态，页面显示“没有待处理动态，本轮不生成执行计划”。

如果存在待处理动态，计划会由后台自动生成，页面显示：

- “确认本次运行计划”：调用 `POST /api/runs/{run_id}/confirm`；
- “开始执行计划”：调用 `POST /api/runs/{run_id}/start`；
- “继续下一条／重新检查当前条目”：仅在运行暂停且允许恢复时出现，调用 `POST /api/runs/{run_id}/resume`。

确认后计划的动态范围、顺序和来源关系不可修改。运行表格只展示序号、动态、流程、页面状态、运行状态。

## 7. 发现规则

当前适配器对配置 UP 执行以下规则：

1. 读取该 UP 的图文/专栏页面；
2. 找到普通抽奖合集和官方抽奖合集；
3. 每个类别按合集后缀数字选择最新的两个合集；
4. 每个选中的合集取最新 5 条来源专栏；
5. 检查来源专栏是否已点赞；
6. 解析来源专栏引用的动态；
7. 按动态 ID 全局去重，但保留一个动态对应的全部来源关系；
8. 已点赞来源专栏标记为已处理，不作为本轮来源点赞目标；
9. 未点赞且解析成功的来源专栏及其动态进入候选范围。

候选动态的官方/非官方流程标签来自来源类别；正式执行时仍会读取动态页面进行运行时确认。

## 8. 官方抽奖执行流程

官方自动化默认开启，配置项为 `BILI_OFFICIAL_AUTOMATION_ENABLED=true`。

每条官方动态按以下顺序执行：

1. 打开 `https://www.bilibili.com/opus/<数字ID>`；
2. 读取动态右侧点赞状态；
3. 若已经点赞，返回 `ALREADY_PARTICIPATED_LIKED`，将条目标记为跳过，不打开抽奖面板；
4. 若未点赞，要求页面存在唯一官方互动抽奖入口 `a[data-type="lottery"]`；
5. 打开互动抽奖入口，等待官方抽奖 iframe 加载；
6. 读取面板文本，面板文本最多轮询约 10 次、每次间隔 500 毫秒；
7. 如果面板先显示“已成功参与”“已参与”“已转发”等终态，返回 `ALREADY_PARTICIPATED`，不点击参与按钮；
8. 如果面板没有“开奖时间”字段，按 `LOTTERY_EXPIRED` 处理并跳过；
9. 如果存在开奖时间，读取参与按钮；只有唯一且文本在允许列表内的按钮才会点击；
10. 点击后最多轮询约 30 次、每次间隔 500 毫秒，等待成功或明确失败终态；
11. 成功后先关闭互动抽奖面板，并确认 iframe 和关闭控件均消失；
12. 面板关闭后点击动态点赞并确认点赞标记点亮；
13. 得到明确终态后，等待下一条官方动态的随机间隔，默认 3–5 秒。

官方参与按钮文本允许列表包括“关注UP主并转发抽奖动态”“关注我并转发抽奖动态”“转发抽奖动态”等有限文本。按钮不唯一、面板读取失败、验证码/风控或点击后终态未知时，当前条目停止，记录问题网址，不自动重试。

## 9. 非官方抽奖执行流程

非官方自动化默认开启，配置项为 `BILI_UNOFFICIAL_AUTOMATION_ENABLED=true`。

### 9.1 运行时分类

- 页面存在唯一官方互动抽奖入口时，判定为官方；
- 只要没有稳定官方入口，就按非官方处理；
- 非官方再根据转发叠层是否存在原动态细分为普通或加码；
- 普通和加码的实际动作策略相同，均使用评论框的“同时转发到我的动态”复选框。

### 9.2 动作顺序和等待

每条非官方动态执行：

1. 打开动态后随机等待 1–2 秒，再进行首次页面读取；
2. 检查当前动态右侧点赞状态；已点赞返回 `ALREADY_LIKED_SKIPPED`，整条跳过；
3. 未点赞时读取当前动态自身正文，不使用评论列表生成要求；
4. 调用 DeepSeek 生成简短评论；
5. 追加动态正文中要求且评论尚未包含的话题标签；
6. 按动态要求从设置表单的固定账号中补充最多 3 个 @好友；
7. 填写评论，勾选“同时转发到我的动态”，点击唯一可见的发布按钮；
8. 评论发布按钮点击完成且没有异常即返回 `COMMENT_SUBMIT_ACCEPTED`，不等待评论列表立即显示；
9. 复核评论同步转发的终态；
10. 随机等待 1–2 秒，点击动态点赞并确认点亮；
11. 随机等待 1–2 秒，打开作者主页并检查关注状态；
12. 通过动态作者的 `space.bilibili.com/<mid>` 链接优先直达作者主页；没有可用链接时，打开作者搜索页，随机等待 1–2 秒，再匹配唯一精确作者；
13. 得到评论、转发、点赞和关注的明确终态后完成本条。

关注按钮、点赞按钮、同步转发控件或作者主页不唯一时，当前条目阻塞并记录问题网址。任何已经发生写入但终态未知的动作都不会自动重试。

## 10. 来源专栏收尾

所有动态进入安全终态后，程序重新计算来源专栏收尾：

- 初始已点赞：显示“已点赞”，不重复点击；
- 初始未点赞、关联动态全部终态且没有开放问题：等待 3–5 秒后自动给来源专栏点赞，并复核点亮；
- 关联动态未全部终态或存在问题网址：显示“阻塞”，本轮不点赞；
- 来源点赞终态未知或失败：记录来源专栏网址，停止收尾，不自动重试。

当前配置 `BILI_SOURCE_LIKE_AUTOMATION_MAX_ITEMS_PER_RUN` 默认值为 `10`，表示一次运行最多自动收尾 10 个来源专栏；可通过环境变量调整。

## 11. 结果状态如何理解

| 状态/代码 | 含义 |
|---|---|
| `completed` | 当前条目动作已获得明确成功终态 |
| `skipped` | 已点赞、已参与或抽奖已结束，未重复写入 |
| `waiting_user` | 页面结构、控件或写入终态需要人工复核 |
| `blocked_unknown` | 点击或读取后的外部结果未知，禁止自动重试 |
| `blocked_failed` | 安全检查或控件检查失败，未允许继续写入 |
| `ALREADY_PARTICIPATED_LIKED` | 动态已经点赞，按已参与跳过 |
| `ALREADY_PARTICIPATED` | 官方互动抽奖面板明确显示已参与，未点击按钮 |
| `LOTTERY_EXPIRED` | 官方互动抽奖面板没有开奖时间字段，按已结束处理 |
| `COMMENT_SUBMIT_ACCEPTED` | 评论发布按钮已点击且未抛出异常，不依赖评论列表即时显示 |
| `UNOFFICIAL_PARTICIPATION_CONFIRMED` | 非官方评论、转发、点赞、关注均已确认 |

页面底部的问题网址列表是本轮安全记录。对应动态或来源专栏在问题未解决前不会自动补点赞。

## 12. 等待时间总览

| 场景 | 默认等待 |
|---|---:|
| 打开非官方动态后首次读取 | 随机 1–2 秒 |
| 非官方评论/转发/点赞/关注之间 | 随机 1–2 秒 |
| 非官方作者搜索页打开后匹配 | 随机 1–2 秒 |
| 官方动态之间 | 随机 3–5 秒 |
| 来源专栏收尾之间 | 随机 3–5 秒 |
| 官方面板文本水合 | 最多约 5 秒（10 × 500ms） |
| 官方参与后终态轮询 | 最多约 15 秒（30 × 500ms） |
| 关闭最后一个控制台页面后释放服务 | 约 3 秒宽限期 |

等待时间是防止页面异步水合和避免连续快速操作的运行策略，不代表 B 站一定会在该时间内完成网络响应；终态不明确时程序会停止。

## 13. 环境变量

源码启动时可以在启动前设置：

```powershell
$env:BILI_PORT = "8787"
$env:BILI_BROWSER_CHANNEL = "msedge"
$env:BILI_OFFICIAL_AUTOMATION_ENABLED = "true"
$env:BILI_OFFICIAL_AUTOMATION_DELAY_MIN_SEC = "3"
$env:BILI_OFFICIAL_AUTOMATION_DELAY_MAX_SEC = "5"
$env:BILI_UNOFFICIAL_AUTOMATION_ENABLED = "true"
$env:BILI_UNOFFICIAL_AUTOMATION_DELAY_MIN_SEC = "1"
$env:BILI_UNOFFICIAL_AUTOMATION_DELAY_MAX_SEC = "2"
$env:BILI_SOURCE_LIKE_AUTOMATION_ENABLED = "true"
$env:BILI_SOURCE_LIKE_AUTOMATION_MAX_ITEMS_PER_RUN = "10"
python -m backend.launcher
```

DeepSeek Key 通过网页设置表单输入，不建议使用环境变量保存；如果必须使用环境变量，变量名为 `BILI_DEEPSEEK_API_KEY`，并应避免把终端历史和日志分享出去。

## 14. 常见问题

### 页面提示端口 8787 被占用

确认是否已有助手实例运行。若已有实例，直接访问 <http://127.0.0.1:8787/>；若不是本软件占用，关闭占用程序后再启动。助手不会强制结束其他程序。

### 点击“打开登录页”没有重复打开页面

这是预期行为：已有登录页时按钮只会把它切换到前台。关闭登录页后再次点击才会创建新页。

### 发现完成但没有执行计划

只有存在待处理动态时才自动生成计划。若所有来源已点赞、动态已参与或没有可解析候选，页面会明确显示不生成空计划。

### 官方条目提示 `LOTTERY_EXPIRED`

当前规则是：互动抽奖面板没有“开奖时间”字段就按已结束处理。该条会跳过，不点击参与按钮。

### 非官方条目提示 `COMMENT_*`、`FOLLOW_*`、`*_NOT_UNIQUE`

表示评论、同步转发、点赞、关注或作者匹配没有唯一且可确认的控件。程序会停止当前条目并保留问题网址，不能通过重复点击强行继续。

### 评论已经发出但界面看不到

当前版本不再复检评论列表。B 站评论可能延迟渲染；只要唯一发布按钮点击没有异常，就记录 `COMMENT_SUBMIT_ACCEPTED`。转发、点赞和关注仍需终态确认。

### 程序停止后是否可以直接继续

只有运行状态为允许恢复且没有外部写入未知结果时，页面才显示“继续下一条／重新检查当前条目”。如果上一次在点击后终态未知，必须人工检查 B 站页面，避免重复评论、转发、点赞或关注。

## 15. 安全和使用注意事项

- 本软件会在已登录的 B 站账号下执行真实评论、转发、点赞、关注和官方抽奖参与动作；点击“开始执行计划”即表示允许这些写操作。
- 执行期间不要手动操作自动化浏览器页面、关闭弹窗或切换目标动态。
- 遇到验证码、风控、登录失效、页面结构变更或控件不唯一时，应停止并人工复核。
- 不要分享包含 Cookie、浏览器会话、DeepSeek Key、数据库或日志的目录。
- `BiliLotteryAssistant.exe` 必须与 `_internal` 目录一起使用。
