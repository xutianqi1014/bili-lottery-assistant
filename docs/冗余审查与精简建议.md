## 2. 正确性问题：先补回归，再修改

### A01：计划 source_section 串值

位置：[execution_plan.py](../backend/use_cases/execution_plan.py)，create 第一轮循环约第 87 行、第二轮持久化约第 147 行。

第一轮逐条计算 source_section 和 action_plan，但 PlannedItem 不保存 source_section。第二轮调用 runs.add_item 时直接读取第一轮结束后遗留的变量：

```python
source_section=source_section,
mode=source_section or "unknown",
```

本次执行原始两段 for 循环、PlannedItem 和原始辅助函数，并捕获 add_item 参数，得到：

| 输入条目 | 预期分段 | 实际分段 / mode | action_plan |
| --- | --- | --- | --- |
| interactive | interactive | reservation / reservation | 仍是互动先判点赞、再分类 |
| reservation | reservation | reservation / reservation | 仍是官方检查流程 |

最后一条无分段时，也会把前面条目的分段清为 None、mode 写为 unknown。此问题发生在**计划构造**，不是网页识别；运行时可能重新修正 mode，不能据此断言每次都会错误写入，但预览和持久化来源线索已不一致。

修改建议：

- 在 PlannedItem 中保存 family 和 source_section，第一轮计算一次，第二轮只读 item 字段。
- 最小修补可在第二轮按该 item.contexts 重算，但会保留重复计算。
- 已执行历史计划不能直接批量重写；待执行旧计划如需修正，应以原始上下文为依据。

验收：一计划同时包含 interactive、reservation、None，顺序置换后逐条正确；多来源同一动态仍保持优先级；动作计划和临时标签一致。现有 [test_execution_plan.py](../tests/integration/test_execution_plan.py) 两例都是单条，不能暴露该错误。

### A02：重复发现覆盖历史来源归属

位置：[activity.py](../backend/db/models/activity.py) 的 ActivityOrigin；[activities.py](../backend/db/repositories/activities.py) 的 add_origin、list_for_discovery、list_origin_contexts。

关系复合键只有 article_id + activity_id，不含 discovery_id。add_origin 命中旧关系后始终把 discovered_in_run_id 更新为新批次；旧预览又按该字段过滤。

静态可推导的触发序列：

1. D1 保存文章 S → 动态 A，归属 D1。
2. D2 再次发现同一 S/A，更新同一行归属为 D2。
3. 查询 D1 时该关系不再匹配，旧候选/上下文减少，统计可能仍是原数量。

已经存入 RunItem 的条目不会自动被删除；风险是发现预览、旧发现建计划和来源解释，不应夸大为整个运行账本丢失。尚未运行 SQLModel 集成复现。

建议把“全局文章包含动态”和“某轮发现的关系快照”分开。新增每轮发现关联表，键包含 discovery、article、activity；每轮位置/分段保存到快照。也可扩充原表键，但须做 SQLite 重建迁移，不能只靠当前加列迁移。

不能通过取消 discovery_id 过滤掩盖问题，否则旧发现混入后来的候选。已被覆盖的历史信息不能凭现有一行完全恢复，应说明迁移恢复范围。

验收：D1/D2 重复发现后两份预览不变；跨来源动态仍全局去重；旧 RunItem 不改写；迁移备份及数据量核对。

### A03：来源收尾默认上限不适配双主页最大范围

位置：[工具人 adapter](../backend/source_adapters/lottery_toolman/adapter.py) 按主页+类别选择；[config.py](../backend/config.py) 第 27 行上限 10；[source_like_automation.py](../backend/use_cases/source_like_automation.py) 第 149 行超限分支。

两个主页可选中三个合集，每合集 5 篇。若文章互不重复且都 ready，共 15 篇；len(ready) > 10 会在任何点击前返回 SOURCE_LIKE_AUTOMATION_SCOPE_TOO_LARGE。不是每轮必现，已点赞/问题/缺少合集都会降低数量。

建议在确认计划前展示数量和上限；若产品决定支持 15，统一调整配置/契约/说明并保留边界。不要删除上限或悄悄截前 10 篇却把整轮标为完成。分批需要持久化批次及总范围限制。

验收：0/10/11/15 个 ready；超限零 transport 调用；调整后的执行仍只针对确认计划内来源。

### A04：前端刷新没有单一所有者

位置：[view.ts](../frontend/src/features/discovery/view.ts) 的 refresh/refreshPlan/selectProfile；[bootstrap.ts](../frontend/src/app/bootstrap.ts) 的 SSE 回调。

每次 running 状态 refresh 都注册新 setTimeout，却未保存/清除 timer；手动刷新、事件和旧轮询可叠加。切来源后旧请求仍可能完成并写回旧 discovery/profile。每个 run.* 事件都全量拉计划，缺少在途合并和旧响应过滤。

建议一个轮询 timer + 请求 generation 或 AbortController；切来源/终态时取消旧轮询，应用响应前核对 ID 和 generation。计划请求按 runId 合并，终态补一次最终刷新；SSE 重连后拉取当前状态。

验收：fake timers 和可控延迟 Promise，覆盖连点刷新、快速切来源、旧响应最后到达、连续事件及终态停止轮询。该竞争尚未浏览器实测。

### A05：同篇文章跨合集入选可能冲突

位置：[discovery.py](../backend/db/models/discovery.py) 的 DiscoverySelection；[discoveries.py](../backend/db/repositories/discoveries.py) 的 add_selection；[discover_source.py](../backend/use_cases/discover_source.py) 逐合集保存。

DiscoverySelection 主键为 discovery + article，add_selection 每次插入；若同文属于两个选中合集，本轮会重复插入同一主键。动态 seen_activity_ids 不解决文章选择层去重。是否有实际线上重叠未验证。

建议一份“本轮文章处理结果”关联多个合集上下文，检查文章只做一次；若只保留主合集，需明确定义优先级和丢弃次来源的语义。与 A02 一起设计。

验收：同文多合集不冲突、不重复打开/写文章，预览能解释来源；同动态跨多篇文章仍只有一个 RunItem。

## 3. 精简建议与保留边界

### S01：明确目录包或单文件包，避免混搭

[app.spec](../packaging/windows/app.spec) 将 a.binaries/a.datas 输入 EXE，随后 COLLECT 又收集同样的依赖/资源，且注释写 onedir。

建议保留目录版交付：EXE 使用 exclude_binaries=True，由 COLLECT 收集依赖与数据；或另设真正单文件 spec，只发布 EXE。不要两套模式揉成一个产物。

本次未重新构建，不能承诺减半或节省具体 MB。验收需比较新旧未压缩/ZIP 体积和文件清单；干净目录解压双击，验证首页/健康接口、前端、两个契约 YAML、默认 Edge 启动；重新计算发布哈希。不要直接从旧包删 DLL。

### S02：收拢作者关注流程，先统一只读辅助函数

[shared/author_follow.py](../backend/activity_engine/shared/author_follow.py) 431 行；[unofficial/transport.py](../backend/activity_engine/unofficial/transport.py) 723 行。

两处都做作者定位、主页直达/搜索、唯一可见控件、状态判断、单击后轮询。AST 发现五组相同函数体：_page_text、_first_text、_author_profile_ids、_attribute、_inner_text。

但关注文案匹配、用户名规范化、URL 解析、等待回退和 FAILED/UNKNOWN 映射并不相同，不能机械替换。先提取只读 DOM primitives 和作者定位结果，再复用写入核心、分别映射调用方结果。发现阶段只读检查不能换成 ensure_author_follow。

验收：外层作者与引用作者同屏、@前缀、直达/搜索、0/2 个候选、延迟渲染、已关注零点击、点击异常 UNKNOWN、页面其他位置“已关注”不误确认目标。

### S03：纯函数和序列化是低风险切入点

- JSON 字符串→dict、非法/非对象返回 {} 的函数体在 9 处重复：discoveries 路由以及 automatic_execution_plan、execution_plan、official_participation_execution、run_execution、source_like_automation、source_like_execution、source_like_plan、unofficial_participation_execution。
- [runs.py](../backend/api/routes/runs.py) 的 get_run 重复传全套配置；已有 _serialize_run_for_state 可复用。
- [title_rules.py](../backend/source_adapters/lottery_toolman/title_rules.py) 的 select_latest_entries 对降序截取后的列表再次同键降序排序，第二次无效。

建议小型 json_utils、复用现有序列化器、删除二次排序。整数列表解析分“JSON 字符串输入”和“已解析对象输入”，不能合并成含混函数；UTC datetime 和 ISO 字符串也不能强改同一返回类型。

验收：非法 JSON、null/数组/对象、数字字符串、bool/int 处理规则；所有运行接口响应一致；limit<=0、空列表、相同排序键不变。

### S04：拆职责而非做万能执行器

[run_execution.py](../backend/use_cases/run_execution.py) 1,561 行，同时负责 queue/restart、页面检查、策略分派、落库、问题、事件、延时和来源收尾。多个 _execute_* 分支重复处理继续/停止结果。

建议顺序：

1. 抽事件 payload 和统一 outcome 保存。
2. 抽只读检查 + 来源策略。
3. 保留薄的串行 orchestrator，把运行迁移/恢复规则独立。
4. 官方/非官方返回一致的协调结果，但各自保留账本和写入条件。
5. 从 671 行 participation_dom.py 分离预约执行与面板观察，避免复制 transport。

不能为了少写 if 删除只读路径、授权或 NO_RETRY。先固定旧运行/旧 checkpoint 特征测试，再搬代码；验证事件顺序、transport 次数、预约、重启和来源策略。

### S05：批量取上下文，一次建立来源索引

[execution_plan.py](../backend/use_cases/execution_plan.py) 的筛选/排序与 [discoveries 路由](../backend/api/routes/discoveries.py) 有按活动查询来源上下文的路径。建议一次加载本轮上下文，按 activity_id 分组，筛选/排序/序列化复用。查询数取决于请求筛选，不能宣称每次固定 2N。

[source_closure.py](../backend/use_cases/source_closure.py) 对每个来源遍历所有 RunItem，反复解析 source_article_ids_json，扫描接近 S×N。建议每条只解析一次，建 source_id→items 索引。

验收：SQL 计数器确认不再随活动数量逐条查询；本地 100/1000 条数据比较结果与耗时；多来源、缺文章、零活动、开放问题和未知标记结果不变。未测量不承诺性能百分比。

### S06：清理已完成 Task

[runner.py](../backend/jobs/runner.py) 的 _tasks 只增不删。用原 JobRunner 类、假事件总线，顺序完成 100 个不同任务后，**len(_tasks)=100、_active_job_id=None**。

建议完成回调清理，并确认字典仍指向该 task，防止误删复用同 ID 的新任务。历史状态放数据库或有界日志，不永久保留 Task；保留全局单任务槽。

验收：大量任务结束后字典有界；异常/取消/shutdown/同 ID 重用/槽忙正常。当前确认对象留存，并未测得严重内存泄漏。

### S07：统一来源接口，保留选择策略差异

[discover_readlists.py](../backend/source_adapters/lottery_toolman/discover_readlists.py) 三个函数重复请求、响应信封和候选转换。可以一份读取/转换 + 三个纯规则：标题族、精确名、年份，不写万能大正则。

[domain/ports.py](../backend/domain/ports.py) 的协议未纳入 select_readlists；发现层 getattr 探测并兼容 dict/list。建议协议统一返回 Sequence[ReadlistCandidate]；如需外部兼容，在一个适配层转换。Nuomi 的 discover_entries 与基类相近，可评估直接继承。

验收：同 family 跨两个主页都保留；两个主页都检查；精确名不接受“抽奖合集2”；年份、位置、发布时间规则不变。不能把“相似适配器”误合并成同一选择条件。

### S08：隔离历史试验路径，逐项清理无引用对象

旧 source_like_plan.py（203 行）、source_like_execution.py（259 行）、source_like_write_test.py（211 行），共 673 行，仍被旧测试链引用，但现行主入口使用 source_like_automation。

建议先归入明确的 legacy/受控工具目录并注明用途；只有确认外部调用和历史状态兼容都不需要后再删除。移动不等于净删 673 行。source_like.py 的 URL 校验和账本仍被当前服务使用，不能一起删。

| 候选 | 仓内证据 | 建议 |
| --- | --- | --- |
| LotteryToolmanConfig | 只有定义 | 确认外部导入后删除/迁移有效配置 |
| stable_class_state | 无调用 | 删除候选，不为复用而改变状态读取语义 |
| SOURCE_CARD* / READLIST_ENTRY | 无使用 | 删除或移入历史说明，保留 ARTICLE_LIKE* |
| HtmlNode.text_parts | 只 append 无读取 | 移除冗余存储，保留有序 content/children |
| GuardedUnofficialActionExecutor | 旧测试和包导出 | 标明 legacy，不删除实际账本 |
| 前端 getRunSourceClosure | 只有定义，页面从 plan.stats 展示 | 可删未用包装，后端诊断接口不必删 |

“仓内未引用”不等于“外部没人用”。包入口、数据库迁移、410 tombstone 不是明显冗余。

### S09：共享前端来源模板，减少全页重绘

[overview-page.ts](../frontend/src/features/discovery/overview-page.ts) 与 [discovery-page.ts](../frontend/src/features/discovery/discovery-page.ts) 重复 activityTypeLabel、sourcePages、选择器和来源信息模板。提取纯 source-profile 组件，用少量参数区分页内按钮/状态，不必换框架。

490 行 DiscoveryView 同时管理网络、轮询、设置、日志和导航。render 替换 root.innerHTML 并重绑事件；run 事件刷新可能覆盖未提交输入/焦点/滚动。先拆日志 store 与刷新协调器，随后仅更新相关页区域，可使用根事件委托。

验收：双主页/来源选择一致；输入设置时收到运行事件不丢输入；日志最多 500 条、脱敏/复制不变。FakeRoot 字符串测试不覆盖真实焦点/事件，需 DOM 或浏览器测试。

- 若干包/构造器注释仍描述早期禁写阶段；使用说明有重复章节号。
- live_contracts 两个入口即使 opt-in 仍 skip，不是线上契约回归已经通过。

建议构建脚本验证解释器/依赖、构建前端、检查资源、逐步检查退出码，再打包/健康冒烟；发布从单一版本源生成或校验其他位置；契约用共享状态 Schema，测试动作顺序与登记一致，验证证据文件存在及范围。不能为通过审计把离线验证改标 WRITE_TEST_PASSED，也不要全局替换历史 CHANGELOG 的旧版本。

### S11：复用来源观察结果，缩短事务

[inspect_marker.py](../backend/source_adapters/lottery_toolman/inspect_marker.py) 和 [extract_activities.py](../backend/source_adapters/lottery_toolman/extract_activities.py) 都会 open 同一未点赞文章；发现保存流程部分 Session 跨 await 页面提取。

建议一次导航读标记/正文，构造目标身份明确的只读观察结果，然后短事务落库。不要跨条目缓存 Locator；写入前的目标、状态、唯一控件复验不是无用重复，必须保留。

验收：少一次明确重复导航；跳转/超时/unknown 仍正确；等待页面不长占写事务；每次真实写入前仍重新确认必要条件。

### S12：账本结构化放在后期

三类执行服务反复读写整个 Run.stats_json，目标越多重复序列化越多；[unofficial_participation_execution.py](../backend/use_cases/unofficial_participation_execution.py) 多次直接调用 ledger._get。

先提供公开只读 checkpoint 查询接口，再测量 JSON 大小和持久化耗时。有必要时拆逐目标/逐动作账本表，统计改派生摘要；旧 JSON 保留读取兼容。这是中高风险迁移，不应先于正确性修复。

保留 unknown/in_progress/attempts/已确认副作用，绝不把写前落盘推迟到一批动作结束，否则崩溃后可能重复执行。

## 6. A01 可复现的源码隔离模拟

在仓库根将下面代码交给 Python 执行。只用标准库，读取原源码 AST；不导入应用、不连接数据库、不启动浏览器。与完整 DB 集成测试互补，不能替代后者。

```python
import ast
from dataclasses import dataclass
from pathlib import Path
from types import SimpleNamespace as N

path = Path("backend/use_cases/execution_plan.py")
tree = ast.parse(path.read_text(encoding="utf-8"))
cls = next(n for n in tree.body
           if isinstance(n, ast.ClassDef) and n.name == "ExecutionPlanService")
create = next(n for n in cls.body
              if isinstance(n, ast.FunctionDef) and n.name == "create")
block = next(n for n in create.body if isinstance(n, ast.With))
loops = [n for n in block.body if isinstance(n, ast.For)]
names = {"PlannedItem", "_item_state", "_primary_family", "_primary_source_section"}
helpers = [n for n in tree.body if getattr(n, "name", None) in names]
future = ast.ImportFrom(module="__future__",
                        names=[ast.alias(name="annotations")], level=0)
scope = {"dataclass": dataclass}
exec(compile(ast.fix_missing_locations(
    ast.Module(body=[future] + helpers, type_ignores=[])), str(path), "exec"), scope)

ordered = []
for i, section in enumerate(["interactive", "reservation"], 1):
    activity = N(id=i, dynamic_id=str(510000000+i), title=section,
                 canonical_url=f"https://www.bilibili.com/opus/{510000000+i}")
    contexts = [(N(source_section=section, source_position=i),
                 N(family="official", selected_rank=i), N(id=i))]
    ordered.append((activity, contexts))
captured = []
scope.update(
    ordered=ordered, request=N(family_order=("normal", "official")),
    item_rows=[], source_ids=set(), open_problem_articles=set(),
    planned_count=0, blocked_count=0, skipped_count=0,
    run=N(id=1), session=None,
    runs=N(add_item=lambda *args, **kwargs: captured.append(kwargs)),
)
exec(compile(ast.fix_missing_locations(
    ast.Module(body=loops, type_ignores=[])), str(path), "exec"), scope)
print([(x["title"], x["source_section"], x["mode"]) for x in captured])
# 基线输出：
# [('interactive', 'reservation', 'reservation'),
#  ('reservation', 'reservation', 'reservation')]
```

其他已执行检查：AST 顶层函数体重复扫描、契约状态集合比对、JobRunner 100 次完成任务的隔离模拟。SQLModel 集成模拟因旧解释器不可启动而未完成，A02/A05 未伪报集成通过。

## 7. 成功标准

精简成功应表现为相同行为、更少重复事实来源、更清晰的职责和可测量的性能/包体改善，而不是单纯文件数或代码行数变少。大文件拆分可能增加文件数；保留必要安全检查比追求删除行数更重要。
